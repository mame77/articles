## はじめに

最近の開発は、ほぼ **Orca** の上で完結しています。
Orca は複数の AI エージェント（Claude Code、Codex、OpenCode など）を、ワークツリーごとにチャットやターミナルで動かせる IDE です。

この記事では、

- 今の Orca の使い方（Claude と Codex の役割分担、自動化している部分）
- 実装前に AI の「1案」を見せてもらって赤ペンを入れる自作スキル **akapen（赤ペン先生）**

について書きます。

## 全体像

```
┌─────────── NixOS サーバー ───────────┐
│  Orca（Xvfb 上で常駐、VNC で同じ画面）│
│   ├ Claude : 要件整理・判断・レビュー │
│   └ Codex  : コードを書く             │
└──────────────────────────────────────┘
        ↑ Tailscale
   ノートPC / スマホから接続
```

Orca はサーバー上で常に動かしておき、手元のノートPCからは VNC やリモート接続で同じ画面を触っています。
どこから触っても同じチャットやワークツリーが続いているのが便利です。

## Claude と Codex の役割分担

一番大きいのはこのルールです。

- **Claude**：要件の整理、方針の判断、Codex への指示、結果の確認、レビュー
- **Codex**：リポジトリ内のコードやテスト、設定ファイルを実際に書き換える

Claude 自身はコードを直接書かず、Orca 上で Codex のチャットを立てて作業を任せます。
終わったら Claude が差分を見て、型チェックやテストを流し、問題なければコミット、そして Codex のチャットを閉じる、という流れです。

こうしている理由は2つあります。

1. **レビューする側と書く側を分けたい**
   自分で書いたコードを自分でレビューすると甘くなりがちです。人間のチーム開発と同じで、別の目が入るほうが安心できます。
2. **使用量の枠を分散したい**
   出力の多い作業を Codex に寄せることで、Claude の枠を判断やレビューに使えます。

このルールは `CLAUDE.md` に書いておき、Claude が毎回同じ動き方をするようにしています。

### Codex の起動は残量の多いアカウントで

Codex は複数アカウントを使っているので、起動するときに **5時間枠の残量が一番多いアカウント** を自動で選ぶ小さなラッパーを作りました。

```sh
orca-codex-best -- agent launch --agent codex --surface chat --json ...
```

どのアカウントも枠が残っていないときは起動せずに止まり、Claude がその旨を報告して自分で作業します。

## Orca まわりで自動化していること

設定はすべて NixOS の flake（nix-config）で管理していて、Orca に足りないところは小さなツールやパッチで補っています。

| やっていること | 内容 |
|---|---|
| プロジェクトの自動グループ分け | 10分おきに、タブが開いているリポジトリを「よく使う」、それ以外を「アーカイブ」に移動 |
| `ghq get` で自動登録 | ghq でクローンしたリポジトリを自動で Orca に追加 |
| マージ済みワークツリーの掃除 | PR がマージされたワークツリーを定期的に削除 |
| PR タブのピン留め | PR が紐付いたワークツリーを開くと、その PR をブラウザタブでピン留め |
| チャットを閉じるコマンド | 作業が終わった Codex のチャットを `orca-chat-close` で閉じる |
| 設定の同期 | サーバーとノートPCで Orca の設定をそろえる |

特に自動グループ分けは地味に効いています。
今触っているプロジェクトだけが上に集まるので、サイドバーがすっきりします。

### チケットごとにワークツリー

Linear のチケットに紐づく作業は、チケット番号の名前でワークツリーを作ります。

```sh
orca worktree create --repo path:<repo> --name ABC-123 --branch mame77/ABC-123 \
  --linear-issue ABC-123 --base-branch develop --json
```

PR を作ったらワークツリーに紐付けておくと、さっきのピン留めで PR がすぐ見られます。

## akapen（赤ペン先生）スキル

ここからが本題のもう1つです。

### 困っていたこと

AI に「いい感じに作って」と頼むと、**決まっていない部分を AI が勝手に仮定で埋めて** 作ってしまうことがあります。
出来上がってから「そうじゃない」と気づくと、やり直しの手間が大きいです。

かといって、実装前に質問を10個も並べられても答えるのが大変です。

### 「1案を見せて、赤ペンを入れてもらう」

そこで作ったのが **akapen** です。名前の通り「赤ペン先生」をイメージしています。

1. AI が、作る前に **1つの案** を HTML の紙面にまとめる
2. 人はその紙面で選択肢を選んだり、気になる場所に **赤ピン** を置いてコメントしたりする
3. 返ってきた「赤ペン回答」を読んでから、AI が実装を始める

Orca のチャットでは、この紙面がそのまま会話の中に表示されます。
［完了］を押すと回答がコピーされるので、チャットに貼って送るだけです。

### こだわったルール

スキルには、AI が守るべきルールを強めに書いています。

- **回答が届くまで実装しない**
- **事実は人に聞かない**
  コードや実行結果を調べればわかることは AI が自分で調べ、根拠（`ファイル:行` など）を添えます。人に聞くのは、好み・優先度・トレードオフだけです。
- **問いは3問前後、最大4問**
  選ばなかった問いは「お任せ」として、推奨案で決めてよいことにしています。
- **質問票にしない**
  UI の話なら、文字だけで聞かずにスクリーンショットや画面の再現を載せます。選択肢ごとに絵・利点・代償・選択欄を1枚のカードにまとめます。
- **必要なときだけ使う**
  単純で解釈が1つしかない依頼では出しません。

### 頼まなくても使ってもらう

最初は「赤ペンして」と言ったときだけ動くスキルでした。
今は `CLAUDE.md` にも書いて、**要件が複雑だったり抽象的だったりして、そのまま作ると仮定で埋める部分が出そうなとき** は、頼まなくても実装前に akapen を使うようにしています。

「どこを聞くべきか」の判断も AI に任せられるようになって、やり直しがかなり減りました。

### Codex でも Claude Code でも

akapen は Codex を主な対象にしつつ、Claude Code でも同じ HTML と Python のスクリプトで動くようにしています。
Orca のチャットでは会話内表示、それ以外の環境ではローカルの小さなサーバーを立ててブラウザで回答する、というように表示方法だけを切り替えています。

## まとめ

- Orca を常駐させ、**Claude が考えてレビューし、Codex が書く** 形に落ち着いた
- Orca に足りないところは NixOS の設定と小さなツールで補っている
- 実装前のすれ違いは、**1案を見せて赤ペンを入れる akapen** で減らせた

AI に任せる範囲が広がるほど、「何を人が決めるか」をはっきりさせるのが大事だと感じています。
同じように AI エージェントを複数使っている人の参考になればうれしいです。
