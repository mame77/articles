## はじめに

Orca で複数の AI エージェントを動かす開発環境については、[別の記事](https://zenn.dev/mame77/articles/orca-multi-agent)にまとめました。
この記事では、実装前のすれ違いを減らすために作った **akapen（赤ペン先生）** スキルを紹介します。

## akapen（赤ペン先生）スキル

### 困っていたこと

AI に「いい感じに作って」と頼むと、**決まっていない部分を AI が勝手に仮定で埋めて** 作ってしまうことがあります。
出来上がってから「そうじゃない」と気づくと、やり直しの手間が大きいです。

かといって、実装前に質問を10個も並べられても答えるのが大変です。

### 「1案を見せて、赤ペンを入れてもらう」

そこで作ったのが **akapen** です。名前の通り「赤ペン先生」をイメージしています。

1. AI が、作る前に **1つの案** を HTML の紙面にまとめる
2. 人はその紙面で選択肢を選んだり、気になる場所に **赤ピン** を置いてコメントしたりする
3. 返ってきた「赤ペン回答」を読んでから、AI が実装を始める

Orca のチャットでは、この紙面がそのまま会話の中に表示されます。
［完了］を押すと回答がコピーされるので、チャットに貼って送るだけです。

### こだわったルール

スキルには、AI が守るべきルールを強めに書いています。

- **回答が届くまで実装しない**
- **事実は人に聞かない**
  コードや実行結果を調べればわかることは AI が自分で調べ、根拠（`ファイル:行` など）を添えます。人に聞くのは、好み・優先度・トレードオフだけです。
- **問いは3問前後、最大4問**
  選ばなかった問いは「お任せ」として、推奨案で決めてよいことにしています。
- **質問票にしない**
  UI の話なら、文字だけで聞かずにスクリーンショットや画面の再現を載せます。選択肢ごとに絵・利点・代償・選択欄を1枚のカードにまとめます。
- **必要なときだけ使う**
  単純で解釈が1つしかない依頼では出しません。

### 頼まなくても使ってもらう

最初は「赤ペンして」と言ったときだけ動くスキルでした。
今は `CLAUDE.md` にも書いて、**要件が複雑だったり抽象的だったりして、そのまま作ると仮定で埋める部分が出そうなとき** は、頼まなくても実装前に akapen を使うようにしています。

「どこを聞くべきか」の判断も AI に任せられるようになって、やり直しがかなり減りました。

### Codex でも Claude Code でも

akapen は Codex を主な対象にしつつ、Claude Code でも同じ HTML と Python のスクリプトで動くようにしています。
Orca のチャットでは会話内表示、それ以外の環境ではローカルの小さなサーバーを立ててブラウザで回答する、というように表示方法だけを切り替えています。

## まとめ

実装前に AI の1案を見て、必要なところだけ赤ペンを入れるようにしました。
AI に任せる範囲が広がるほど、「何を人が決めるか」をはっきりさせるのが大事だと感じています。
